About EMOS

We are building the operating layer that lets electronic‑materials discovery run as one system instead of a dozen disconnected tools.

Discovery was fragmented by design

AI-driven materials discovery has never lacked capability. It has lacked cohesion. Each database exposes its own schema, each generative model emits its own structure format, and each property predictor expects its inputs in a particular shape. To connect any two, a researcher writes bespoke, project-specific glue code, and rewrites it for the next project.

That overhead sits squarely between a scientific idea and a result. It is where momentum is lost.

Standardize the core, extend at the edges

EMOS defines input and output contracts by Information Unit type, so databases, generators and predictors all plug into the same workflow pattern. Property names from every source are mapped through one framework-level corpus into a shared vocabulary.

A database's output can feed a predictor with no adapter. A generator's structures are compared on the same property scale. Every stage writes to one provenance and logging layer, so benchmarking and reproducibility come for free rather than as an afterthought.

Three layers that build on each other

The base layer. Databases, generators and predictors, each exposing one standardized method (retrieve, generate or predict) over CIF structures and a shared property schema, so any two can interoperate without bespoke glue code.

The composition layer. Higher-level workflows that assemble one or more Information Units into an end-to-end task, such as the Database Extractor or Stability Consensus analysis.

The layer you touch. A guided form for running single units and features, and a node editor for fully custom drag-and-drop pipelines, served over a decoupled REST backend.
